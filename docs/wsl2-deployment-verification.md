## 真实流程验证

1. 初始化中台并启用 `Codex` 接单程序，确认后端监听、执行端在线。
2. 从 `Windows` 浏览器打开操作台，使用本人密钥连接；页面显示“实时同步中”。
3. 执行真实 `try`，通过现有中转站调用模型，生成“试跑：选一个颜色”卡片。
4. 在网页选择“绿色”并提交，观察新轮次接单和执行。
5. 中台确认轮次 `#4` 为 `done`，摘要为“你选了绿色，试跑通过”；卡片 `#2` 为 `done`，结果相同。

早先失败的试跑轮次 `#2` 已通过公开停止接口取消，保留了原始记录，不再自动重试；它关联的旧卡片保留为已回答但未执行完成，用于说明当时的真实状态。

## 部署中修正的问题

`Codex` 的一次调用可能先输出断线重连错误，随后恢复并输出最终答案与 `turn.completed`。原适配器保留早先的错误，导致已完成的业务被中台当作失败重试。

已在 `tests/adapters.test.ts` 增加先失败的行为复现，并在 `plugins/codex/agent.ts` 的完成事件处理中清除此前的错误。只影响已有完成事件的读取；没有完成的调用仍按错误处理，未修改中台协议或调度。

## 当前限制

- 中转站恢复原会话时曾返回 `list_turns is not supported yet`；接单程序使用已有的未开始轮次恢复逻辑另开会话，随后完成试跑。完整原会话续接能力仍取决于该中转站与 `Codex CLI` 的兼容情况。
- `WSL` 中缺少 `notify-send`，桌面通知无法发出；网页接收和处理卡片已验证。
- 模型额度按中转站实际使用计量，费用未上报时不能将页面显示的金额视为实际免费。
