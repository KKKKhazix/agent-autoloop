# 前后端启动步骤

适用仓库：`D:\github\agent-autoloop`。按下面的路线选一种执行，不需要两种都跑。

| 你的目的 | 使用路线 |
| --- | --- |
| 先打开页面，看流程、卡片和操作效果 | 路线一：`Windows PowerShell` 演示模式 |
| 让真实的命令行 `Agent` 接活、执行、提问并继续 | 路线二：`WSL2` 完整运行 |

原生 `Windows` 的完整后端尚未作为支持平台：初始化仍会调用 `/bin/sh`，不能只加 `--no-service` 就当作兼容。下面的演示模式已在本机使用真实中台和浏览器验证；完整运行按仓库安装说明使用 `WSL2`、`Linux` 或 `macOS`。

## 路线一：在 Windows 上先打开流程操作台

这条路线无需安装或登录任何命令行 `Agent`，不会调用模型，也不会发送真实通道消息。后端是真实的中台，数据是隔离的测试数据。

### 第一步：安装前端依赖

打开一个 `PowerShell` 窗口，执行：

```powershell
cd D:\github\agent-autoloop
node --version
npm --version
npm --prefix frontend ci
```

`Node.js` 需要 `24` 或以上。`npm ci` 首次启动或锁文件变化后再执行，平时不用重复安装。只启动页面及测试中台，不需要安装根项目的开发依赖。

### 第二步：启动后端，保留窗口一

在同一个窗口执行：

```powershell
npm --prefix frontend run fixture
```

等终端输出类似下面的信息：

```json
{
  "url": "http://127.0.0.1:随机端口",
  "owner": "本次生成的本人密钥",
  "source": "本次生成的来源密钥",
  "worker": "本次生成的测试接单密钥",
  "home": "本次测试数据目录"
}
```

实际输出在一行里。记住 `url`、`owner`、`source`，保持这个窗口运行。每次启动都会生成新的端口和密钥，不要使用上一次的值。

### 第三步：启动前端，保留窗口二

再打开一个 `PowerShell` 窗口，执行：

```powershell
cd D:\github\agent-autoloop
$env:AGENT_AUTOLOOP_URL = Read-Host "粘贴窗口一输出的 url，然后回车"
npm --prefix frontend run dev
```

输入的是完整地址，例如 `http://127.0.0.1:62850`，不要带外层引号。以你这次的实际输出为准。

等终端打印 `Local` 地址。通常是：

```text
http://127.0.0.1:5173
```

如果端口被占用，前端可能选择其他端口，请打开终端实际打印的地址。

### 第四步：在网页连接中台

1. 打开窗口二打印的页面地址。
2. 在“本人密钥”中粘贴窗口一输出的 `owner`。
3. 点击“连接中台”。
4. 看到“已连接”、执行记录和问题卡片，就说明前后端已连通。

页面通过实时事实订阅更新状态；断线时显示数据可能过期，恢复连接后按序号续读。可以查看轮次详情、回答“是否继续修复？”、给通知结案。

演示中没有持续接活的执行程序：回答后出现新排队轮次是正常现象；停止运行中轮次需要执行端确认，因此不能把“停止请求已提交”当作实际进程已停。要让真实 `Agent` 持续执行，使用路线二。

### 第五步：尝试发送事件（可选）

点击网页右上角“发送事件”，填写：

| 字段 | 填什么 |
| --- | --- |
| 来源密钥 | 窗口一输出的 `source`，不是 `owner` |
| 事件编号 | `demo-001` |
| 事件类型 | `feedback.new` |
| 事项对象 | `#44` |
| 一句话摘要 | 测试页面发出的事件 |
| 详细资料、原始链接 | 可以留空 |

点击“发送事件”。同一来源再次发送相同事件编号，中台会去重；想创建另一条事件，请改为 `demo-002` 等新编号。

### 第六步：停止

在前端窗口和后端窗口分别按 `Ctrl+C`。

测试数据目录是窗口一输出的 `home`。脚本会尝试清理；如果目录仍在，先确认两个窗口都已停止，再手工删除这个明确的临时目录。不要删除你正式使用的中台数据目录。

## 连不上时按顺序检查

| 现象 | 检查方式 |
| --- | --- |
| 页面打不开 | 窗口二是否仍运行；打开它实际打印的前端地址 |
| 页面能打开，中台连接失败 | 窗口一是否仍运行；`AGENT_AUTOLOOP_URL` 是否等于后端地址 |
| 修改后端地址后没生效 | 停止前端，再设置环境变量并重新启动；只刷新网页不能改变代理目标 |
| 密钥无效或权限不符 | 连接页面用 `owner`；发送事件用 `source`；演示模式重启后密钥会变 |
| 页面没有业务数据 | 正式中台尚未收到匹配事件时为空是正常的；路线二可通过 `try` 触发 |
| 刷新页面后需要重新连接 | 正常，密钥只在页面内存中，不会持久保存 |
| 初始化找不到 Agent | 在运行后端的同一个环境检查命令及登录；不要混用 Windows 和 WSL 的安装 |
| 原生 Windows 初始化报 `/bin/sh` 等错误 | 使用路线一看界面，或在 WSL2 中按路线二启动完整系统 |
