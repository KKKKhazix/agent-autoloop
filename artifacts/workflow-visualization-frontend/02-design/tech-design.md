# 实时流程操作台技术方案

## 决策及约束

使用独立 `frontend/` 的 `Vue 3`、`TypeScript`、`Vite` 单页客户端。复用现有 `/v1` 协议；不修改 `kernel/`、`host/`、`protocol/`，不新增业务接口，不新增数据库、调度或认证系统。根包无运行时依赖。用户已确认在本仓库加入客户端，对原来不收总览界面的约定作本次必要调整。前端与中台分别启动。

应用使用原生 `fetch` 和平台表单，简单流程由 `CSS` 布局及原生 `SVG` 连接线实现；不引入图编辑库、组件库、状态管理库或路由。新增依赖限 `vue`、`vite`、`@vitejs/plugin-vue`、`vue-tsc`、`typescript`、必要的 `@types/node`，版本由实现阶段读取官方包注册信息后锁定到独立锁文件。不要猜测未来版本，不复制根包的未来版本要求。当前环境 `Node 26.13.0`、`npm 11.20.0`，没有可用 `git` 工作树或根依赖；主线程负责根安装。

已应用 `vue-coding-standards`、`vue-best-practices`、`vue-project-structure`、`vue-component-structure`、`search-first`、`ponytail`、`karpathy-guidelines`、`design-ui`。没有可用 `tech-design` 技能，按角色直接产出本方案。官方 `Vite` 与 `Vue` 文档的网页工具查询没有返回内容，因此此处不宣称已核实具体版本；实现时用官方包注册信息确认兼容。

## 已核对的接口

| 行为 | 请求与鉴权 | 响应/注意事项 |
|---|---|---|
| 总览 | `GET /v1/state`，本人密钥 | `totals/cards/recentCards/sources/lines/agents/channels/elsewhere/runs/unrouted/spending/now/timezone` |
| 历史 | `GET /v1/state?before=<nextBefore>` | 每页 `60` 轮，`hasMore/nextBefore` 为游标；只有首页额外包含所有活动轮次 |
| 追溯 | `GET /v1/runs/:id/why`，本人密钥 | 事实数组 `{version,seq,at,type,changes,meta?}`；`changes` 含 `{table,key,row}`，配置事实也在内 |
| 回答 | `POST /v1/cards/:id/answer`，本人密钥 | `{choice:零基选项}` 或 `{text:回答}`；也可组合，不发送通道的 `by/ref`；以最新状态确认 |
| 结案 | `POST /v1/cards/:id/resolve`，本人密钥 | `{reason:非空说明}`，最多 `1000` 字；返回 `{changed}` |
| 停止 | `POST /v1/runs/:id/cancel`，本人密钥 | `{}`；显示停止请求已提交，不能当作进程已停；轮次仍以真实状态呈现 |
| 事件 | `POST /v1/events`，独立来源密钥 | `{id,type,subject?,summary?,detail?,link?}`；响应有 `event/duplicate/routed`，不能使用本人密钥 |

`Card` 由 `kernel/query.ts` 的 `cardView` 生成：`id/version/kind/state/title/text/options/recommend/choice/answer/by/result/link/rule/createdAt/decidedAt/closedAt`。总览没有卡片对应轮次编号，不得按规则名把卡片伪关联到某一轮。轮次详情从 `why` 中的卡片变更读取真实 `run_id` 和回答关系。

`Run` 总览包含 `id/rule/agent/state/attempts/createdAt/claimedAt/finishedAt/notBefore/summary/error/link/session/usage/stopping/events`。`events` 最多近期 `20` 条，只有来源、类型、对象、摘要及链接。详情需读 `why`，不能将列表当作完整事件历史。可读 `why` 中的 `run_events` 关联得到该轮事件，参照 `cli/why.ts` 的关联方法，不导入命令行显示函数。

总览并不提供全局独立事项数量；图上的“事项”是概念节点，选中轮次时展示规则和资料中的对象，不推断未公开的全局事项数。用量如实显示未上报数量，不把缺省当成零成本。

## 数据流和请求生命周期

首版采用完成后间隔 `3` 秒的串行自动刷新，以及手动刷新。主线程已确认此选择。总览没有日志游标；从 `0` 读取完整历史事实流会增加首屏负担，故本批不实现 `SSE`。界面明确写“每 3 秒自动刷新”“上次更新”，不伪称推送或在线进程状态。

`useConsole` 拥有连接凭据、首页状态、加载过的历史、游标、选择轮次、详情、读取错误和操作状态。网络调用放在 `service/hub.ts`，纯投影与状态文案放在 `model.ts`，类型放在独立 `types.ts`。不将整个后端 `stateOf` 依赖引入浏览器；用局部明确的查询响应类型，未知字段忽略。可复用 `protocol/client.ts` 的端点/错误约定，但它没有外部取消信号、返回类型为宽泛值，本次用小型带信号的 `fetch` 服务，而非改动公共客户端。

- 连接：新代次、取消上次请求、清空旧数据和详情，再拉首页；凭据仅在内存，刷新页面后重新输入。
- 自动刷新：首页覆盖总览；历史轮次按编号合并去重，首页活动轮次覆盖旧副本，保留已加载历史及其游标，不能周期刷新重置翻页。旧连接/旧轮次响应不得覆盖当前状态，使用取消信号及代次校验。
- 详情：选择变更立即清空旧详情并加载；后台只在相关轮次或卡片状态变化时刷新，不能清空正在输入的表单和失去焦点。不把旧轮次错误显示为新轮次错误。
- 失败：保留同一连接已读状态但明确“数据可能已过期”，显示上次成功时间、错误和重试入口；断开连接取消定时器和请求，并清空凭据与业务数据。重复连接只有一个刷新循环。
- 操作：每次明确按目标提交，进行中禁用重复提交；停止与结案先展示确认及目标，结案必填说明。请求成功后立即刷新首页及对应详情，不能因后台刷新失败把已成功写操作显示为未执行。超时或网络断开时写操作不自动重发，提示结果未确认并允许先刷新核对。
- 来源发送：独立来源密钥由发送表单临时持有，不落盘；稳定事件编号由用户输入，发送失败后保留编号，重试可被后端去重。表单中的 `source` 仅作说明不能让请求冒充来源。

## 界面和交互

视觉采用现有架构图的暖灰背景 `#faf9f5`、近黑正文 `#1d1c19` 与陶橙强调 `#c2491d`；白色面板、细边线、系统中文字体、适量圆角，不使用大面积渐变和外部字体。页面以“流程运行台”为标题，明确这是当前中台的真实运行情况。

- 顶栏：名称、连接/陈旧状态、上次更新时间、刷新、连接设置、发送事件。连接设置折叠为轻量区域，未连接时可见，包含本人密钥密码输入和权限说明。
- 首行指标：运行中、排队、待处理卡片、今日结束及真实用量。数值来自 `totals` 和 `spending`，未连接用占位符，不能用假数字。
- 主流程：左侧来源 → 中间规则/事项 → 执行/回执 → 右侧卡片，底部回答后回到事项的回路；通过中文状态与数量说明哪个环节需要关注。节点是可聚焦按钮，点击筛选或展开其真实资料。无需拖动、缩放或编辑。
- 下方主区：左侧筛选与轮次列表，右侧选中轮次详情。搜索规则、编号、对象、摘要；状态筛选按钮带 `aria-pressed`。列表显示状态文字、规则、摘要、时间及编号，支持加载更早记录。
- 详情：事件、执行与回执、卡片回答时间线，步骤有时间和类型。支持查看未截断的原文，外部文字只用插值/文本，不渲染 `HTML`，链接只允许可信协议的显式点击；会话自定义协议需允许名单或改作可复制文字。
- 待办区：所有开放卡片独立展示，不依赖列表选择；问题提供原始选项和补充文字，普通通知可“已处理”，开放卡片可带理由结案。仅告知卡片不显示回答按钮。
- 桌面约 `1280` 及以上：流程横向，轮次与详情双栏；平板压缩留白；窄屏 `390` 左右堆叠流程及详情，无页面横向滚动，卡片和按钮可换行。
- 错误用文字及图形提示，危险操作按钮可辨识；键盘完整到达所有入口，焦点可见，确认对话使用原生 `dialog` 或可访问内联确认；支持减少动态效果。

## 文件及函数级边界

建议约 `7` 个职责明确组件：根 `App.vue` 协调布局，`ConnectionPanel` 管连接表单，`FlowOverview` 管图及节点选择，`RunList` 管搜索/状态/翻页，`RunDetail` 管时间线和停止确认，`CardInbox` 管问题/结案，`EventComposer` 管来源发送。类型均定义在 `types.ts` 而非组件内；单组件的输入草稿放组件本身，后台刷新不能重建卡片组件键。

`service/hub.ts`：创建固定同源客户端及状态/详情/四种写操作，所有鉴权通过请求头，JSON 错误映射为中文；支持 `AbortSignal`。`model.ts`：流程筛选、状态标签、关联事实投影、安全链接判断。`hooks/useConsole.ts`：连接及读写生命周期、自动刷新、合并历史。组件以 `props/emits` 通信，不加无用通用组件层。

## 同源接入和交付

`vite.config.ts` 读取仅服务端可见的 `AGENT_AUTOLOOP_URL`（默认指向文档中的本机中台地址），开发与本地预览均将固定 `/v1` 路径代理给该目标；浏览器只能请求本站 `/v1`，不能通过参数改变代理目标。服务仅监听回环地址，不用 `VITE_` 环境变量存任何密钥。代理转发调用者的 `Authorization`，不自动注入本人密钥，不将访问密钥放查询参数，不启用凭据 Cookie。

`npm run dev` 用于开发，`npm run build` 生成 `dist/`；`npm run preview` 只作本机验收。正式部署用静态服务器托管 `dist` 并固定反向代理 `/v1`，在 `frontend/nginx.conf` 提供最小示例；公网使用 `HTTPS` 并由维护者部署，不在本次任务发布。静态根与 API 代理是同源，反代不能设置放行通配跨域。

根 `tsconfig.json` 只包含明确的后端目录，无需更改；前端自己的 `tsconfig` 处理浏览器和配置类型。根格式检查通配会覆盖前端 `ts/json`、构建产物和本地 `artifacts`：新增 `.prettierignore` 排除 `frontend/dist/`、`artifacts/`，根 `.gitignore` 忽略构建产物；源码仍通过项目的格式检查，前端单独格式检查要覆盖 `.vue` 与 `CSS`。不要格式化无关后端。

文档任务同步 `AGENTS.md`、`docs/protocol.md`、`docs/architecture.svg`、`README.md`、`README.en.md`、`INSTALL.md`、`skills/agent-autoloop/SKILL.md`、`SECURITY.md`；原“中台没有界面”改为“内核不提供界面，仓库提供独立操作台客户端”。原无总览能力的陈述改成存在独立客户端，不承诺编排器。检查示例是否包含旧约定，但只改实际冲突。

## 测试与验收

仓库“测试写在实现之前”优先于通用角色模板把测试留到末尾的要求。开发前先写以下最小行为测试，运行确认失败，再实现：

- 服务把本人/来源凭据用于正确端点，错误鉴权与非成功响应不能当成功；写请求不自动重放。
- 客户端生命周期在重新连接或切换轮次后拒绝旧响应；断线标陈旧，重复连接不建立多套轮询；分页与刷新合并去重。
- 详情事实关联只展示对应事件/轮次/卡片，外部文字与危险链接不执行。

测试采用 `node:test`（运行 `tests/*.test.ts`，无需新测试框架），头部用英文写失败方式。Vue 反应式状态测试可用 `effectScope` 或最小公开接口，不要求测试私有实现细节。浏览器验收由 `TASK-04` 用实际浏览器验证 UI 与临时真实中台：隔离临时 HOME/随机端口，不启动真实 Agent、不发送真实通道消息，通过协议领取并交测试回执，走一遍事件→提问→回答→接续、停止、结案；另测未授权、连接失败、空态、窄屏和文本安全。可加 `frontend/tests/fixture.ts` 为浏览器提供独立临时中台，启动前先设置临时环境，再动态导入 `host/http.ts`，退出关闭连接、清理临时目录。

执行前端测试、类型检查、构建及格式检查，根 `npm run test:quick`、`npm run typecheck`、`npm run format:check`。本方案不修改内核、日志或并发调度，无需模拟、强杀或变异。当前环境没有 `.git`，不把此限制误报为代码失败；无 `bash` 时不依赖安装冒烟脚本完成首版验收。
