## ما المشكلة التي يحلها؟

غالبًا ما نستخدم وكلاء سطر الأوامر مثل Claude Code أو Codex من خلال "مراقبة محطة": تكتب أمرًا، تشاهده يعمل، وتجيب على أسئلته. إذا أغلقت النافذة أو ابتعدت، يتوقف العمل.

**Agent Autoloop** يحول وكلاء سطر الأوامر لديك إلى حلقة في الخلفية. في المركز **نواة** محددة छूट من الاعتمادات الزمنية. حولها، مصادر الأحداث، الوكلاء، قنوات الإشعارات، وحتى خطوط تسليم CI/CD كلها **إضافات** قابلة للتبديل.

- **آلة واحدة، أمر تثبيت واحد.** يعمل على جهاز Mac أو Linux الخاص بك. لا حاجة لخادم سحابي أو منافذ واردة.
- **ربط وكيل جديد في سطر واحد.** لا حاجة لـ SDK، ولا حاجة لتعديل كود الوكيل. أي أداة سطر أوامر تأخذ أمرًا وتطبع ردًا نهائيًا يمكنها التوصيل.
- **لا لوحة تحكم على الويب.** البطاقات تصل إليك على فيسبوك، DingTalk، WeCom، Slack، Discord، أو إشعارات سطح المكتب عندما تحتاجك. كل شيء آخر على بعد أمر واحد.

## البدء

يعمل على macOS وLinux. تحتاج Node 24، Git، curl، وأي وكيل سطر أوامر مسجل دخول بالفعل؛ لا حاجة لحساب GitHub. يمكنك أيضًا إعطاء [دليل التثبيت](INSTALL.md) لوكيلك وتركه يثبّت كل شيء لك.

```bash
curl -fsSL https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.sh | sh
```

ثم شغّل حلقة حقيقية مع وكيلك الخاص — اسأل، اخرج بينما ينتظر، اتخذ القرار، استأنف:

```bash
agent-autoloop try
```

> مخرجات CLI والسلاسل الإشعارية الافتراضية حاليًا بالصينية.

## كيف تتدفق قطعة عمل

الأرقام تتطابق مع المخطط أعلاه:

1. **حدث وارد.** مهمة مجدولة في الساعة 9 صباحًا، أو Issue جديد على GitHub، أو تنبيه إنتاج يصبح حدثًا قياسيًا يُرسل إلى النواة.
2. **التوزيع وفقًا لقواعدك.** قواعدك تقرر أي وكيل يتعامل معها وفي أي مجلد. الأحداث الجديدة لنفس الموضوع بينما هي في الطابور تندمج في جولة واحدة.
3. **اعمل جولة واحدة واخرج.** الوكيل يضع परिणामه في رسالته الأخيرة، وت 종료 العملية.
4. **يسأل فقط عند الحاجة.** للإجراءات الحساسة مثل حذف البيانات، إعادة تشغيل خدمة، إنفاق مال، أو مراسلة أشخاص، ترسل النواة لك بطاقة عبر فيسبوك أو إشعار سطح المكتب. بينما تأخذ وقتك، لا procés وكيال يعمل ولا تُنفق توكنات.
5. **لمسة واحدة تستأنفها.** إجابتك تلتقط المحادثة الأصلية وتنهي العمل.

أيthing يمكن للوكيل التعامل معه بمفرده يأخذ الحلقة التلقائية في الأعلى: ينتهي فورًا، أو يحدد فحص متابعة (مثلاً بعد 30 دقيقة) دون إزعاجك.

## الاستخدام اليومي

### اكتب قواعدك (`rules.json`)

لا حاجة لكود لاصق. افتح `~/.agent-autoloop/rules.json` وتحت `rules`، أعلن **ماذا حدث، من يتعامل معه، وأين يعملون**. اجعل `to` اسمًا موجودًا تحت `agents`. على سبيل المثال، اكتب Brief صبحي كل يوم في الساعة 9:

```json
{
  "name": "Brief صبحي",
  "when": { "cron": "0 9 * * *" },
  "to": "codex",
  "cwd": "~/notes",
  "prompt": "لخص ملاحظات yesterday وCommits إلى Brief اليوم."
}
```

الأحداث الخارجية تعمل بنفس الطريقة بمجرد توصيل المصدر. لتسليم Issues GitHub جديدة إلى Codex، سجل أولاً `github` تحت `sources` ([دليل](skills/agent-autoloop/SKILL.md#접一个事件插件)):

```json
{
  "name": "تعامل مع Issues",
  "when": { "source": "github", "types": ["issues.opened"] },
  "to": "codex",
  "cwd": "~/code/app",
  "skill": "handle-issue",
  "parallel": 3
}
```

التغييرات تصبح سارية خلال ثوانٍ من الحفظ. شغّل `agent-autoloop check` للتحقق. إذا ارتكبت خطأ، يستمر المحور في تشغيل القواعد السابقة الصالحة ويبعث لك بطاقة تشير إلى الخطأ.

### كيف يتحدث الوكلاء مرة أخرى إلى المحور

يطلب المحور أمرًا واحدًا فقط من الوكيل: **ضع نتيجتك في رسالتك الأخيرة**. عندما ينتهي العمل، سطر استنتاج واحد يكفي. لأسألك شيئًا، يضيف الوكيل كتلة `agent-autoloop`:

```text
تم فحص الطلب. لدينا مخزون كافٍ في المستودع.

```agent-autoloop
{
  "ask": [{
    "title": "كيف نشحنه؟",
    "text": "كلا الخيارين يمكن أن يشحنا اليوم.",
    "options": ["شحن سريع", "استلام ذاتي"],
    "key": "shipping"
  }]
}
```

```

بصرف النظر عن `ask`، يمكن للإيصالات إرسال إشعارات (`notice`)، حل بطاقات مفتوحة (`resolve`)، جدولة فحوصات متابعة (`later`)، وإطلاق أحداث جديدة (`events`). إذا كان JSON غير صالح، يجعل المحور الوكيل يعيد كتابة تلك الرسالة الأخيرة فقط في نفس الجلسة، دون تكرار العمل المنجز. إذا فشل إعادة الكتابة أيضًا، يحتفظ بالاستنتاج الأصلي ويخبرك أن الإيصال لم يُطبّق.

## آليات النواة الأربع

النواة حوالي 1,650 سطرًا مع صفر من الاعتمادات الزمنية. لا تقرأ ساعة، لا تستخدم عشوائية، ولا تصدر طلبات خارجية؛ الإضافات تتصل، والبيانات الاعتمادية تبقى مع الإضافات التي تستخدمها. المدخلات المتطابقة تعطي نتائج متطابقة دائمًا. تجلب أربع أنظمة أنماط مثبتة إلى وكلاء سطر الأوامر:

- **انتظار بدون تكلفة**: العملية تخرج أثناء انتظار اتصالك، وحالة الانتظار تعيش في SQLite، لذلك لا يبقى وكيل على قيد الحياة. إذا أجبت بعد ثلاثة أيام، لا procés وكيال يعمل ولا تُنفق توكنات في intervening — فقط المحور الخفيف ينتظر في الخلفية؛ إجابتك تستأنف المحادثة الأصلية.
- **تسجيل الأحداث**: كل الحالة مستمدة من سجلوقائع مضاف فقط، يُرفق في نفس معاملة SQLite مع فهارسه قبل أن يرد المحور. الوقائع المؤكدة تنجو من `SIGKILL`، كل جولة يمكن تتبعها بأمر واحد، وتغييرات الصيغة تعاد بناؤها من السجل بدون برامج ترحيل.
- **تقسيم الكود / البيانات**: مثل SQL المعلم. عناوين Issues، أجسادها، ونصوص خارجية أخرى تُكتب فقط إلى ملف بيانات محلي، nunca إلى الرسالة، التي تحمل فقط أنواعًا، معرّفات، وروابط مدققة بالأحرف؛ `rules.json` وحده يقرر أي وكيل يعمل، في أي مجلد، ومع أي وصول. الأحداث الحاملة لـ `cwd`، `agent`، أو `access` تُرفض صراحة.
- **مقطع circuit breaker للهوبات**: مثل TTL الحزمة في الشبكات. الأحداث التي يعيدها وكيل يمكن أن ترسل المزيد من الوكلاء، وعدد الهوبات يستمر في النمو — عبر أسئلة humans والمتابعات المجدولة أيضًا — ولا يمكن للوكيل إعادة تعيينه. بعد 8 هوبات، يسجل المحور الحدث، يتوقف عن الإرسال، ويبعث لك بطاقة إشعار.

## تخطيط المستودع

| الموقع | المحتويات |
|---|---|
| `kernel/` | قرارات، سجل وقائع، إسقاطات، مواعيد نهائية، مطابقة قواعد، سلوك نقطة نهاية، نماذج بطاقات |
| `host/` | عقدة HTTP، ملفات واتصالات SQLite، ساعة، تكوين، خدمات خلفية، تحميل إضافات |
| `protocol/` | تنسيقات سلك، JSON Schema، التحقق من المدخلات، عميل HTTP، فحوصات مطابقة |
| `worker/` | ادعاء عمل، تشغيل وكلاء، معالجة نبضات وإلغاء، قراءة وإرسال إيصالات |
| `cli/`، `bin/` | أوامر المستخدم ونقطة دخول: حالة، إجابات، `why`، MCP، تحديثات، إزالة تثبيت |
| `plugins/` | إضافات وكيل، حدث، قناة، وتسليم مضمنة |
| `examples/recipes/` | وصفات كاملة مع قواعد، مهمة Skill، وتعليمات إعداد |
| `examples/plugins/`، `examples/skills/`، `examples/*.sh` | قوالب إضافات بسيطة، أدلة مهام مستقلة، وأمثلة Shell |
| `skills/agent-autoloop/` | دليل تكوين وتشغيل المحور، متاح أيضًا للوكلاء أثناء التثبيت |
| `docs/` | بروتوكول، دليل إضافات، ومخططات معمارية صينية / إنجليزية |
| `tests/`، `sim/` | اختبارات سلوك يومي، محاكاة، تعداد، اختبارات انهيار، وفحوصات طفرة |
| `scripts/`، `.github/workflows/` | فحوصات أداء ووكلاء حقيقيين، سكريبتات اختبار تثبيت، و CI Linux / macOS |
| مستندات الجذر و `install.sh` | READMEs صينية / إنجليزية، تثبيت، أمان، إرشادات تطوير، ترخيص، ومثبت |

ابدأ القراءة من `bin/agent-autoloop.ts` → `cli/main.ts`، ثم اتبع الميزة إلى `host/`، `worker/`، أو `plugins/`. اقرأ [البروتوكول](docs/protocol.md) لتصميم النواة. بشكل مشابه، الملفات التي تحمل أسماء تخدم طبقات مختلفة: `host/http.ts` يحول طلبات Node بينما `kernel/http.ts` يحدد سلوك نقطة النهاية؛ `protocol/rules.ts` يتحقق من المدخلات بينما `kernel/rules.ts` يحدد أنواع القواعد ومطابقتها.
