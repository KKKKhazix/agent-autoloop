# 从目标开始循环

Autoloop 已有队列、回执和项目规则。这套配置把规划、起草和审查接成一个闭环。中控通过固定规则把任务交给对应执行角色，结果再回到该项目的同一个规划角色。

流程强制为：起草 → 审查 → 未通过则修正 → 再审查。只有最新草稿经过审查、验收通过，规划角色才能结项。执行角色说“做完了”不代表验收通过；阻塞后只能停止。达到轮数上限仍未通过时，由程序直接停止并等待人工检查，不再调用规划模型，不记为完成。

默认模式用于文字草稿和审查。代码模式见下文。文字模式中，每次模型调用使用独立临时目录，不开放 Shell、项目文件、Git 推送或部署。三个角色当前都调用本机 Codex CLI；审查角色使用独立调用，读取实际草稿，不沿用起草角色的会话。

在接单机上准备项目配置，填写唯一项目编号、目标、验收条件和最多执行轮数。轮数指起草、审查的执行次数，不包括规划；范围为 1 到 4。两次起草、两次审查共 4 轮，结果回到规划角色时恰好是内核的 8 跳上限。

```json
{
  "id": "release-notes",
  "goal": "为小版本升级拟一份说明",
  "acceptance": "说明备份、升级、验证和回退的具体操作",
  "requiredText": ["备份", "升级", "验证", "回退"],
  "maxRounds": 4
}
```

`requiredText` 是可选的程序验收：最多 8 项，每项最多 120 字，逐字检查草稿是否包含全部文字。未满足时，即使模型声称通过也会被拒绝。它适用于可明确写成文字条件的任务，不证明操作已经执行或外部事实正确。语义验收由独立审查调用负责；涉及真实业务效果仍需外部验证或人工验收。

任务文字最多 700、任务验收最多 400、执行或审查输出最多 1000、引证最多 350；这些交接字段的预算包含 JSON 转义，保证草稿和审查意见一起传递时也不超过协议上限。

每次审查沿用被审草稿所属起草轮的任务验收条件，规划角色不能在审查时把它缩减。修正可以定义新的任务条件；项目目标和项目验收条件始终不变。每次调用的三分钟总时限由生成规则中的正式 worker 执行，超时停止整个进程树。

审查必须返回 `verdict: "pass"` 或 `"revise"`，`evidence` 必须引用实际草稿的一段原文。交接层把审查绑定到原始草稿，模型不能替换它。两项 `goal-<项目编号>-tasks/results` 来源用于内部回执，不要为外部发布者签发它们的来源密钥；持有某来源密钥即有权发布该来源的事件，不能把它交给不可信发布者。修正角色同时收到草稿和审查意见；修正后的草稿必须重新审查，旧的通过结论不能代替新审查。

用下面的命令生成规则片段。把它的 `sources`、`agents` 和 `rules` 合入中控规则，保留已有条目。把接单机名称换成实际名称。执行 `agent-autoloop check`，待规则生效后启动。每次启动使用新的目标运行编号。

```sh
node examples/recipes/goal-loop/run.ts rules /absolute/path/project.json mac-lan
agent-autoloop run "release-notes 目标规划" --subject "$(node -p 'crypto.randomUUID()')"
```

`status` 显示各轮状态，`why` 显示任务及回执。目标、项目配置和执行角色由规则确定。模型提交的额外字段、跨项目事件和不匹配的执行能力会被拒绝。请在该目标运行结束后再编辑配置。

这些约束仅属于本示例，不改中台 HTTP 协议、插件接口或内核跳数限制。旧项目配置仍可读取；旧版审查输出缺少明确结论时不再接受。更新脚本后请使用新的目标运行编号，避免继续使用旧的在途交接。

## 真实模型验收

以下命令会调用本机已登录的 Codex CLI，消耗真实模型用量，不发送通知、不推送或部署：

```sh
node examples/recipes/goal-loop/real.ts --run /absolute/path/report.json
```

脚本在临时目录、随机本地端口启动真实中台，由正式 worker 运行生成的命令，包含心跳、回执解析和 HTTP 提交。已知不完整的旧稿作为验收输入；规划、起草、审查、修正和复审全部由真实模型产生。脚本断言首次审查为 `revise`、草稿发生修改、复审为 `pass`、最终文字通过程序验收，最后才结项且没有待领任务。共 9 次模型调用，不预设任何模型输出；失败立即退出并保留已取得的报告，不自动重试成“通过”。每次模型调用的临时目录位于该轮 worker 目录中，确认退出后由验收脚本一起清理；无法确认退出时保留目录。报告路径必须是尚不存在的文件；无法创建时在启动前失败。中断和异常退出时，通过 worker 取消任务并等待进程树退出，之后关闭中台、删除临时数据；即使报告写入失败也执行清理。报告保留输入、各轮交接、失败回执及拒绝原因和最终结果，不含密钥；无法确认退出时也记录保留目录的位置。


## 本地代码任务

目标仍来自本地配置和手动启动，不读取 GitHub Issue。代码模式从指定本地仓库的 `main` 提交建立独立副本，不覆盖原仓库的已提交或未提交文件。模型以 JSON 提交完整文件内容，执行器只应用白名单内的修改，再执行固定验收命令；模型没有 Shell，也不能选择目录、命令或权限。

```json
{
  "id": "local-math",
  "goal": "修复安全除法，除数为零时抛出 RangeError",
  "acceptance": "普通除法和除零测试通过，代码审查无遗留问题",
  "maxRounds": 4,
  "code": {
    "repository": "/absolute/path/local-project",
    "files": ["src/math.mjs"],
    "check": ["node", "--test", "tests/math.test.mjs"],
    "checkFiles": ["tests/math.test.mjs"]
  }
}
```

沿用上面的规则生成命令启动；规则名变为 `local-math 目标规划`，每个目标运行仍使用新的 UUID。`repository` 必须是可信本地 Git 仓库根目录，且已有 `main` 分支。只支持修改 main 上已有的普通文件：最多 12 个、单文件 24000 字、整体 JSON 文件上下文 48000 字；不通过符号链接访问文件，不修改测试入口、测试目录、包脚本或配置策略。新增文件、安装依赖和大规模改造不在这个最小入口内。

`check` 是配置维护者指定的参数数组，直接执行，不拼接 Shell；工作目录是代码副本。参数逐项保留，包括空参数和首尾空格；测试路径使用副本内相对路径，不能用绝对路径或 `--root=...` 等选项指回原仓库。`checkFiles` 必须显式列出验收配置、断言及测试辅助脚本（使用 npm 脚本时也包括它实际调用的验收脚本），这些文件来自固定的 main，不能列入修改白名单；执行器核对真实路径，符号链接别名也不能绕过。验收命令必须在全部测试及其子进程结束后才返回，不能使用启动后台服务即退出的脚本。代码模式会执行项目测试和被修改的代码，只用于你信任的本地项目及验收脚本；独立副本用于保护原工作区，不是执行不可信第三方代码的安全沙箱。

模型回执先校验再写入代码；已完成并记下回执的起草轮重放时复用结果，不重复调用模型或测试。测试命令应可重复执行，且不得承担部署或其他外部业务操作。重放旧轮次只返回该轮历史回执，不回退当前源码；审查和结项始终核对当前版本。未检查的新代码不会沿用旧版本的测试日志。两条日志流持续读取并持久化各自末尾 8000 字，输出多不会截断测试本身。每次验收有独立标识；未结束的新验收不能沿用旧的通过证明，中断前已取得的日志仍可采集。Windows 的原始非零退出码也会保留，只有 `0` 能形成通过证明。

实际源码、Git 差异和测试日志保存在本地运行目录，事件只携带摘要、代码哈希、真实测试退出码和通过标记。独立审查读取实际代码、差异及测试输出；测试未通过时不能给出通过回执。修正后重新跑测试，旧测试和旧审查不能验收新的代码。最终规划结项前再次核对当前代码哈希与已通过的证据。

代码副本保存在 `<AGENT_AUTOLOOP_HOME>/goal-code/<项目编号>/<运行编号>/workspace`，同级 `check.json` 保存真实测试输出。结项不会自动提交、推送、合并或部署；先查看 `git -C <副本目录> diff` 再由你接纳改动。副本跨轮保留，导出所需差异后可删除该运行编号的目录；不要在运行中改项目配置或该目录。

真实代码验收命令：

```sh
node examples/recipes/goal-loop/real.ts --run /absolute/path/code-report.json code
```

它创建临时本地 Git 仓库及固定的普通除法、除零验收脚本。真实模型先做不完整修复，真实测试失败，独立审查要求修正；修正后测试成功、复审通过，最后才结项。报告保留首轮和最终代码哈希、真实退出码、最终代码和差异，并核实原仓库未被修改。中途失败时也会保存当时已取得的候选和测试日志；无法保存报告或采集现场时保留临时目录。文字模式仍可使用原命令运行。
