# 从目标开始循环

Autoloop 已有队列、回执和项目规则。这套配置把规划、起草和审查接成一个闭环。中控通过固定规则把任务交给对应执行角色，结果再回到该项目的同一个规划角色。

流程强制为：起草 → 审查 → 未通过则修正 → 再审查。只有最新草稿经过审查、验收通过，规划角色才能结项。执行角色说“做完了”不代表验收通过；阻塞后只能停止。达到轮数上限仍未通过时，由程序直接停止并等待人工检查，不再调用规划模型，不记为完成。

这个入口用于文字草稿和审查。每次模型调用使用独立临时目录，不开放 Shell、项目文件、Git 推送或部署。三个角色当前都调用本机 Codex CLI；审查角色使用独立调用，读取实际草稿，不沿用起草角色的会话。

在接单机上准备项目配置，填写唯一项目编号、目标、验收条件和最多执行轮数。轮数指起草、审查的执行次数，不包括规划；范围为 1 到 4。两次起草、两次审查共 4 轮，结果回到规划角色时恰好是内核的 8 跳上限。

```json
{
  "id": "release-notes",
  "goal": "为小版本升级拟一份说明",
  "acceptance": "说明备份、升级、验证和回退的具体操作",
  "requiredText": ["备份", "升级", "验证", "回退"],
  "maxRounds": 4
}
```

`requiredText` 是可选的程序验收：最多 8 项，每项最多 120 字，逐字检查草稿是否包含全部文字。未满足时，即使模型声称通过也会被拒绝。它适用于可明确写成文字条件的任务，不证明操作已经执行或外部事实正确。语义验收由独立审查调用负责；涉及真实业务效果仍需外部验证或人工验收。

任务文字最多 700、任务验收最多 400、执行或审查输出最多 1000、引证最多 350；这些交接字段的预算包含 JSON 转义，保证草稿和审查意见一起传递时也不超过协议上限。

后续审查和修正沿用第一轮起草的任务验收条件，规划角色不能在下一轮把它缩减。每次调用的三分钟总时限由生成规则中的正式 worker 执行，超时停止整个进程树。

审查必须返回 `verdict: "pass"` 或 `"revise"`，`evidence` 必须引用实际草稿的一段原文。交接层把审查绑定到原始草稿，模型不能替换它。两项 `goal-<项目编号>-tasks/results` 来源用于内部回执，不要为外部发布者签发它们的来源密钥；持有某来源密钥即有权发布该来源的事件，不能把它交给不可信发布者。修正角色同时收到草稿和审查意见；修正后的草稿必须重新审查，旧的通过结论不能代替新审查。

用下面的命令生成规则片段。把它的 `sources`、`agents` 和 `rules` 合入中控规则，保留已有条目。把接单机名称换成实际名称。执行 `agent-autoloop check`，待规则生效后启动。每次启动使用新的目标运行编号。

```sh
node examples/recipes/goal-loop/run.ts rules /absolute/path/project.json mac-lan
agent-autoloop run "release-notes 目标规划" --subject "$(node -p 'crypto.randomUUID()')"
```

`status` 显示各轮状态，`why` 显示任务及回执。目标、项目配置和执行角色由规则确定。模型提交的额外字段、跨项目事件和不匹配的执行能力会被拒绝。请在该目标运行结束后再编辑配置。

这些约束仅属于本示例，不改中台 HTTP 协议、插件接口或内核跳数限制。旧项目配置仍可读取；旧版审查输出缺少明确结论时不再接受。更新脚本后请使用新的目标运行编号，避免继续使用旧的在途交接。

## 真实模型验收

以下命令会调用本机已登录的 Codex CLI，消耗真实模型用量，不发送通知、不推送或部署：

```sh
node examples/recipes/goal-loop/real.ts --run /absolute/path/report.json
```

脚本在临时目录、随机本地端口启动真实中台，由正式 worker 运行生成的命令，包含心跳、回执解析和 HTTP 提交。已知不完整的旧稿作为验收输入；规划、起草、审查、修正和复审全部由真实模型产生。脚本断言首次审查为 `revise`、草稿发生修改、复审为 `pass`、最终文字通过程序验收，最后才结项且没有待领任务。共 9 次模型调用，不预设任何模型输出；失败立即退出并保留已取得的报告，不自动重试成“通过”。每次模型调用的临时目录位于该轮 worker 目录中，确认退出后由验收脚本一起清理；无法确认退出时保留目录。报告路径必须是尚不存在的文件；无法创建时在启动前失败。中断和异常退出时，通过 worker 取消任务并等待进程树退出，之后关闭中台、删除临时数据；即使报告写入失败也执行清理。报告保留输入、各轮交接、失败回执及拒绝原因和最终结果，不含密钥；无法确认退出时也记录保留目录的位置。
